          Result & inference
          

            Both variants produce the same sorted output; they differ only in how the pivot is chosen before partitioning. On already-sorted or reverse-sorted input, always picking the last element as pivot creates the most unbalanced possible splits, pushing deterministic quicksort toward its O(n²) worst case. Randomizing the pivot breaks that correlation with input order, so its comparison count stays close to the n log n average regardless of how the input arrives — the trade is a small amount of extra work (one random draw and swap per call) for protection against adversarial or already-structured input.
